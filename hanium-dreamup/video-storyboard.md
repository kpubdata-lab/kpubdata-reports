- 참고 형식: CUBRID Lab 소개 영상의 설계 문서([`cubrid-lab/showcase` `projects/cubrid-lab/intro-video/VIDEO_DESIGN.md`](https://github.com/cubrid-lab/showcase/blob/main/projects/cubrid-lab/intro-video/VIDEO_DESIGN.md)). 샷 단위 콘티, 분량 검사, 정직성 원칙을 같은 방식으로 씁니다.

## 1. 개념

**한 줄:** *공공데이터를, 바로 쓰는 테이블로.* 명세 하나로 수집부터 게시까지 검증하고 기록하는 플랫폼, KPubData Builder와 Studio.

소리가 없으므로 **자막이 설명을 맡고, 화면이 증거를 맡습니다.** 시연 장면은 모두 실제 녹화이고, Studio 화면을 원래 크기에 가깝게(93%) 보여 줘서 서비스 전체가 보이게 합니다. 확대는 최대 약 1.25배로 줄였습니다. 바탕은 흰색, 로고와 색은 KPubData Brand v2를 씁니다.

### 보는 사람

1. 공모전 심사위원: 1분 30초 안에 "무엇을 해결했고, 실제로 동작하는가"를 판단
2. 결과보고서를 함께 읽는 사람: 보고서의 기능과 차별점이 실제 화면으로 이어지는지 확인

### 전달 순서

1. **공공데이터는 바로 쓰기 어렵다**: 형식 차이, 정제 반복, 이력 부재
2. **명세 하나로 검증하고 기록한다**: BuildSpec → Builder 실행 → Manifest
3. **서비스 전체**: Studio의 주요 메뉴를 한 번 둘러봄
4. **코드 없이 웹에서 끝까지**: 찾기 → 만들기 → 실행 확인 → 분석 → AI 도우미 → 게시 준비
5. **믿을 수 있다**: 실행 전 검증, 단계별 결과, 읽기 전용 스냅샷, 승인 후에만 실행하는 AI

### 넣지 않는 것

작업대, 리포트 작성, 연결·설정, 관리 화면, 검증 실패 예시, 개발 환경과 테스트, 문제 해결 과정. 시장 규모·OECD 순위는 원문 확인 전이라 쓰지 않습니다.

## 4. 화면 설계

### 4.1 색과 글꼴

영상 전체를 **흰 바탕**으로 만들고, 로고와 색은 KPubData Brand v2를 따릅니다. 기준은 kpubdata-studio의 `docs/brand/VISUAL_IDENTITY.md`와 `assets/logo/kpubdata-brand-assets/`입니다.

| 쓰임 | 값 | Brand v2 이름 |
|---|---|---|
| 바탕 | `#FFFFFF` | Surface |
| 카드·창 모형 테두리 | `#E5E7E2` | Border |
| 제목, 본문, 화면 문구 | `#172033` | Ink |
| 보조 문구, 구간 표시(01·02…), suffix | `#64748B` | Slate |
| 강조 선, 선택 표시 | `#2563EB` | Brand Blue |
| 데이터 흐름 선 | `#06B6D4` | Data Cyan |
| 문제 표시(Q1) | `#B91C1C` | 상태 색 Failure |

- **로고**: K 심볼(`video/symbol_light.svg`, kpubdata-studio `fe5b774`에서 복사)을 고치지 않고 씁니다. 회전, 그림자, 그라데이션, 빛 번짐, 3D를 넣지 않습니다.
- **이름**: `KPubData`가 주인공이고 `Builder` · `Studio`는 더 작고 Slate색입니다.
- **색의 양**: 화면 대부분은 흰색과 Ink입니다. Blue·Cyan·Mint로 넓은 면을 채우지 않습니다.

글꼴은 Pretendard(`video/PretendardVariable.woff2`, SIL OFL 1.1)와 JetBrains Mono(코드)입니다. 제목 88 px / 800, 화면 문구 38~76 px, 자막 33 px / 600.

### 4.2 녹화 화면 배치

- 창 모형: 1344×840(Studio 1440×900 화면의 93%) + 제목 줄 30 px, 화면 위쪽 78 px부터. 서비스 화면이 거의 다 보입니다.
- 화면 문구: 창 모형 위 한 줄(구간 표시 + 문구). 오른쪽에 "실제 Builder 연동 · 공공데이터포털 API" 또는 "데모 모드 · mock 데이터" 표시
- 자막: 창 모형 아래(960 px부터) 짙은 남색 띠에 흰 글자. 샷 시작 0.2초 뒤에 나와 끝나기 0.13초 전에 사라집니다.
- 확대: 콘티의 확대값을 40%만 반영합니다(`ZOOM_DAMP = 0.4`, 최대 약 1.25배). 2배 넘게 빨리 돌린 구간은 창 오른쪽 위에 "×N"을 표시합니다.

### 4.3 엔드 카드

T1과 같은 흰 바탕, 같은 배치에 `KPubData Builder · Studio`를 더합니다. 맨 아래 작은 글씨: "화면: 실제 실행 녹화 · AI 도우미 장면은 데모 모드 · 음성·음향 없음".

팀명, 과제 번호, 학교, GitHub 조직 주소는 넣지 않습니다.

## 5. 자막

- 모든 설명은 자막입니다. 화면 문구(창 위 한 줄)는 장면의 요점, 자막(아래 띠)은 설명입니다.
- 한 샷에 자막 하나. 공백을 뺀 글자 수가 1초당 9자를 넘지 않게 합니다(`video_caption_budget.py`).
- 자막은 영상에 입히고, 같은 내용의 `.srt`도 만듭니다(유튜브 자막 트랙용).

## 6. 녹화 사양

녹화는 [`video/rec/`](video/rec/)의 Playwright 스크립트로 합니다. 순서와 명령은 [`video/README.md`](video/README.md) 4장에 있습니다.

- **화면**: Xvfb 가상 화면(2880×1800)에 Google Chrome을 키오스크 모드로 띄우고, 1440×900 CSS 픽셀·배율 2로 그립니다. ffmpeg x11grab으로 30 fps 녹화합니다.
- **커서**: Playwright 입력은 X 포인터를 움직이지 않아서 페이지 안에 커서와 클릭 표시를 그립니다(`lib.cjs`).
- **글꼴**: 녹화 머신(리눅스)에는 한글 시스템 글꼴이 없어 녹화 브라우저에서만 Studio의 시스템 글꼴 자리(`--font-sans`)에 Pretendard를 지정합니다. 화면 내용과 동작은 바꾸지 않습니다.
- **Builder**: [`serve-builder.sh`](video/rec/serve-builder.sh)가 빈 작업 디렉터리로 단일 사용자 개발 모드(인증 생략)를 띄웁니다. 게시 전 개인정보 검사 필수(`KPUBDATA_BUILDER_REQUIRE_PII_SCAN_FOR_PUBLISH=true`)를 켭니다.
- **Studio**: 실제 연동(5199 → Builder 8010)과 데모 모드(5198, G1만) 두 개를 띄웁니다.
- **명세**: [`apt-trade-gangnam.yaml`](video/rec/apt-trade-gangnam.yaml). 서울 강남구(11680) 2024년 9월 거래분 224건입니다. 조회 조건은 화면에서 입력하고, 나머지 규칙은 촬영하지 않는 구간에 위저드의 YAML 편집 모드로 적용합니다.

| 녹화 | 동작 | 길이 | 쓰는 샷 |
|---|---|---|---|
| rec-01-catalog | 카탈로그 "아파트" 검색 → 시작 | 7초 | D1 |
| rec-02-configure | 조회 조건 입력(이후 YAML 적용은 녹화하지 않음) | 10초 | D2 |
| rec-03-preview-run | 미리보기·검증 → 검토 → 테이블 만들기 → 실행 상세 완료·품질 | 21초 | D2, D3, R1, R2 |
| rec-04-table | 테이블 상세 → 스냅샷 탭 | 6초 | A1 |
| rec-05-sql | 스냅샷 선택 → SQL 입력 → 실행하고 저장 → 차트로 보기 | 23초 | A2 |
| rec-06-publish | 게시 준비 상태 → 데이터 카드 | 8초 | G2 |
| rec-07-assistant | 데모 모드 Ask KPubData 질문 → 근거·제안 → 승인 | 16초 | G1 |
| rec-08-overview | 홈 → 카탈로그 → 테이블 → 갱신 이력 → 품질 → 모니터링 | 14초 | O1 |

녹화 중 확인한 것:

- 처음 명세에서는 개인정보 `block` 정책이 실제로 빌드를 막았습니다. 컬럼명 규칙(`NM`·`NAME` 포함)이 `aptNm`, `roadNm` 같은 원천 컬럼을 개인정보 의심 컬럼으로 잡았습니다. 값이 아니라 컬럼 이름 때문이라 해당 컬럼의 이름을 바꿔(`apartment`, `road` 등) 통과시켰습니다.
- Studio 위저드는 YAML에 `metadata` 키가 없거나 소스 `schema`에 `required`·`dtypes`가 없으면 적용하지 못합니다(`src/features/add-data/model.ts`의 `applyBuildSpecToDraft`). 명세에 빈 값을 넣어 피했습니다.

## 7. 원칙

### 7.1 익명 원칙

블라인드 평가이므로 팀원을 짐작할 수 있는 정보는 영상 어디에도 넣지 않습니다(학교 정보 포함).

| 넣지 않는 것 | 나올 수 있는 곳 | 처리 |
|---|---|---|
| 이름, 팀명, 과제 번호 | 엔드 카드, 화면 문구, 자막 | 쓰지 않음 |
| 학교·학과, 학교 로고·교표 | 엔드 카드, 배경, 바탕화면, 브라우저 탭 | 쓰지 않음. 키오스크 모드로 탭·주소창이 안 보임 |
| 개인 이메일, 학교 메일(`ac.kr`) | 로그인 화면, 사용자 메뉴, 관리 화면 | 개발 모드(인증 생략, 사용자 `dev`)로 녹화 |
| GitHub·Hugging Face 계정명, 조직 주소 | 엔드 카드, 게시 위치 | GitHub 주소는 넣지 않음. 게시 위치는 입력하지 않음 |
| 컴퓨터 사용자명, 홈 경로 | 파일 업로드 창, 터미널, 주소창 | 녹화 화면에 나오지 않음 |
| 목소리, 얼굴 | 내레이션, 웹캠 | 음성 없음, 웹캠 없음 |

- 유튜브 채널 이름과 영상 제목·설명에도 이름과 학교를 쓰지 않습니다.
- 영상 파일의 메타데이터는 `build-final.sh`가 지웁니다.

### 7.2 정직성 원칙

1. 시연 샷은 모두 실제 녹화입니다. 결과 값을 고치거나 합성하지 않습니다. 빨리 돌린 구간은 2배 넘으면 "×N"으로 표시합니다.
2. 데모 모드로 찍은 샷은 G1 하나입니다. 녹화 머신에 LLM API 키가 없어서입니다. Studio가 응답에 표시하는 "DEMO · mock 데이터"를 가리지 않고, 화면 위에 "데모 모드 · mock 데이터" 표시를 따로 붙입니다. 나머지 샷은 모두 실제 Builder와 공공데이터포털 API로 찍었습니다.
3. 게시는 준비 상태 점검과 데이터 카드까지만 보여 주고 게시 버튼은 누르지 않습니다. 자막도 "게시할 수 있습니다"로 씁니다.
4. 촬영하지 않은 구간(YAML 적용)은 콘티와 녹화 사양에 적어 둡니다.
5. 성능 수치는 쓰지 않습니다.
6. [8. 사실 근거](#8-사실-근거)에 없는 주장은 하지 않습니다.
